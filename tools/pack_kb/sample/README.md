# Original synthetic fixtures

`recipes.json` is an explicitly normalized runtime-dump-shaped **fictional** source, not a dump of GTNH. `sample:` IDs and `pack_version: synthetic` distinguish it from pack evidence. The sole `ore:synthetic:Imaginary` identity deliberately tests unresolved symbolic leaves. Machine metadata and voltage values are invented and stored under `synthetic_metadata`.

`store.json` is generated by the stdlib fixture script:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m tools.pack_kb.sample.generate
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tools/pack_kb/tests -v
```

Set `TMPDIR` to a scratch directory before running the tests. Tests refuse to silently use the system temporary directory.

The extractor reads only the explicit recipe source, hashes its actual UTF-8 bytes, and assigns JSON-pointer provenance. The script attaches explicit fictional metadata with pointers into that same hashed source. It never opens a real jar, private directory, config, or runtime store. Recipes exercise Cartesian alternatives, whole batches, catalysts, stochastic outputs, disabled recipes, cycles, fluids, and symbolic prerequisites. Coverage explicitly leaves `runtime_registry_complete` false.

Tests generate minimal synthetic class files and archives in `TMPDIR` using Python byte packing, not a Java compiler. No class files, jars, actual pack bytes, or private data are shipped. Source hashes, provenance pointers, exact regeneration, and the combined JSON-fixture byte budget are asserted by the suite.
